## 2025-03-12 - [Security Enhancement] Secure Order Number Generation
**Vulnerability:** The application was using `Math.random()` to generate the random portion of order IDs in `apps/web/server/api/routes/orders.ts` and `apps/web/app/routes/api.create-order.ts`. `Math.random()` is not cryptographically secure and predictable.
**Learning:** When using `crypto.getRandomValues()` to generate random strings, do not use `.substring(0, N)` on the resulting integer converted to base36. Smaller generated numbers produce shorter strings, leading to a strong statistical bias toward lower digits (like '1') at the start of the string.
**Prevention:** Always use `.slice(-N)` to extract the trailing characters from a random integer's base-N representation, and pad strings appropriately.
## 2024-05-18 - [Insecure Randomness via Math.random]
**Vulnerability:** The application was using `Math.random()` to generate the random portion of order IDs and image keys in `apps/web/app/routes/api.create-order.ts`, `apps/web/app/routes/api.upload-image.ts`, `apps/web/server/api/orders.ts`, and multiple Worker files. `Math.random()` is not cryptographically secure and predictable.
**Learning:** Security IDs and random keys must be unpredictable, meaning we must use secure random generation mechanisms instead of pseudo-random methods.
**Prevention:** Use the Web Crypto API (`crypto.getRandomValues()`) for secure random string generation instead of `Math.random()`. Convert to base36, pad with leading zeros, and use `.slice(-N)` (never `.substring(0, N)`) to extract the trailing characters to prevent statistical bias.
