## 2024-05-18 - Fix Authorization Bypass in Image Proxy Referer Validation
**Vulnerability:** A loose regex (`/^https?:\/\/(.*\.)?ozzyl\.com/`) was used to validate the `referer` and `origin` headers in the image proxy middleware. Because it used a greedy `(.*)` and lacked trailing anchors, it allowed attackers to bypass the validation using malicious URLs like `https://attacker.com/page?p=.ozzyl.com` or `https://ozzyl.com.attacker.com`.
**Learning:** Naive regex matching for domains can easily be bypassed if strict start, end boundaries, and valid character classes for subdomains are not used. The `.*` matcher is particularly dangerous.
**Prevention:** Always use safe parsing libraries (e.g., `new URL(origin).hostname`) when validating domains, or if regex must be used, enforce strict subdomain characters (`[a-zA-Z0-9-]+`) and anchor the end of the domain string (e.g., `(?:\/|$)`).
